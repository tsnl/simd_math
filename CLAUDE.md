# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`simd_math` is a Rust library crate (published to crates.io) providing SIMD-accelerated vector, quaternion, matrix, transform, and AABB math for games, graphics, and robotics. It is built on `std::simd` (`#![feature(portable_simd)]`), so it **requires nightly Rust** — the toolchain is pinned in `rust-toolchain.toml` and picked up automatically by cargo/rustup.

## Commands

```sh
cargo test                      # run all tests (unit + integration)
cargo test test_name            # run a single test by name
cargo test --test integration_test  # run only tests/integration_test.rs
cargo clippy -- -D warnings     # lint; CI fails on any warning
cargo fmt -- --check            # check formatting (CI-enforced); drop --check to fix
```

CI (`.github/workflows/ci.yml`) runs exactly these three jobs: test, clippy with `-D warnings`, and fmt check. All must pass.

Releases are made via the manually-dispatched Publish workflow, which bumps the version in `Cargo.toml`, tags, and publishes to crates.io. Do not hand-bump the version as part of ordinary changes.

## Architecture

All modules (`vector`, `quaternion`, `matrix`, `transform`, `rect`) are re-exported flat from `src/lib.rs`, so everything is `simd_math::TypeName`.

**Newtype-over-SIMD pattern.** Every type wraps a `std::simd` vector (e.g. `SimdVec3(pub(crate) f32x4)`). The inner `.0` field is `pub(crate)`, so cross-module code inside the crate manipulates raw SIMD lanes directly; the public API never exposes it.

**Padding-lane invariant.** 3-lane types are backed by 4-lane SIMD vectors with the fourth lane kept at zero (`SimdVec3` = `f32x4`, `SimdIVec3`/`SimdUVec3` = 4-lane too). Constructors zero the pad lane, and any new operation must preserve that invariant (see `SimdUnitQuat::imag()` for an example of masking the fourth lane). Beware of lane-wise operations where a zero pad lane is not neutral (e.g. products or divisions across all lanes), and note that derived `PartialEq`/`PartialOrd` compare the pad lane as well.

**Macro-generated impls in tiers.** Vector types and their trait impls are generated by macros in `src/vector.rs` with three tiers: `impl_uint_simd_vec!` (basic ops) → `impl_int_simd_vec!` (adds `Neg`) → `impl_float_simd_vec!` (adds norm/normalize/lerp/clamp/powf). Rect types (`SimdRect2/3`, `SimdIRect2/3`, `SimdURect2/3`) are likewise generated by `impl_simd_rect!` in `src/rect.rs`. To add a method across all vector or rect types, extend the appropriate macro, not individual impls.

**Key type semantics:**
- `SimdUnitQuat` is stored as `(s, x, y, z)` and is *always* unit-norm — constructors normalize, and `inverse()` relies on this (it is just the conjugate). Preserve this invariant in any new constructor.
- `SimdMat4` is actually a 3×4 affine matrix: four `SimdVec3` columns (three transformed basis vectors + translation). It is not a general 4×4 matrix.
- `SimdTransform` is position + rotation only (no scale).
- Rects are min/max AABBs; union uses the `|`/`|=` operators (with vectors or rects), intersection uses `&`/`&=`, with `union_identity()`/`intersection_identity()` as fold seeds.

**Conventions (from README.md):** arrays are the interchange format (`From<[T; N]>` both ways); there are no `.x`/`.y`/`.z` accessors — use indexing `v[0]`; vectors are column vectors, multiplication is `Matrix * Vector`; matrices are column-major (each constructor argument is a column, as in OpenGL/GLM); right-handed coordinate system.

## Tests

Unit tests live inline in each `src/*.rs` file and are themselves macro-generated per type (e.g. `test_simd_vec_float_methods!` in `src/vector.rs`) — extend the test macros when extending the impl macros. Broader behavioral tests live in `tests/integration_test.rs`; its `test_readme_example()` mirrors the README code example, so keep the two in sync when either changes.
